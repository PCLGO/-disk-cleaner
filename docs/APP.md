# 磁盘清理助手

“磁盘清理助手”是 Windows 10 22H2 / Windows 11 x64 的本地磁盘盘点与清理工具。当前版本为 `0.1.0-beta`。

## 已实现功能

- 首页显示所有本地固定磁盘的容量、已用和可用空间。
- 快速清理使用 53 个内嵌规则族、139 个路径模板，检查用户与 Windows 临时目录、错误报告，以及多配置浏览器、Electron 应用、开发工具、显卡、游戏平台和 Adobe 等明确缓存。规则族支持多版本、多用户配置和通配目录；明确缓存按软件和用途汇总，近期生成的缓存不会因此整项漏报。
- 快速清理页默认选择 Windows 所在盘（通常为 C:），可主动切换到 D: 或“所有本地磁盘”。系统盘按高置信规则扫描；非系统盘额外执行最多三层的浅层定向检查，列出常见缓存目录和 ≥ 512 MB 的疑似大文件，同时跳过游戏库、WindowsApps、Program Files、回收站和系统卷信息。深度扫盘与重复文件扫描也采用相同的系统盘默认值。
- 首页的每张磁盘容量卡都是扫描目标入口；点击 C: 或 D: 卡片会选中对应磁盘并切换到快速清理页，但不会自动开始扫描。确认目标后，再点击“开始快速扫描”执行只读扫描。
- 快速清理页会汇总“扫描发现”“保守建议可清理”“可重建缓存”和“需查看后决定”。主流程固定为“扫描 → 保守选择或全部选择 → 清理已选”；“全部选择”后按钮原位变为等宽的“取消全选”，扫描期间才显示“取消扫描”。
- 扫描完成后默认高亮第一项供阅读，但不会勾选清理。候选表已经显示实际或疑似身份和精确路径，紧凑详情卡只补充判断依据、清理影响和建议操作，避免重复占用列表高度。所有内嵌规则仍必须完整提供身份、依据、用途、影响和建议。
- 深度扫盘持续输出大文件及名称疑似缓存、日志的目录，显示权限遗漏；支持暂停、继续和取消。
- 每个候选显示精确路径、大小、归属、究竟或疑似是什么、判断依据、影响、置信度、风险、建议操作和大小统计完整性。
- 重复文件按大小、首尾抽样、完整 SHA-256 三级确认；同一 NTFS 文件 ID 的硬链接不会重复计算。
- 软件卸载只读取系统登记信息并调用原卸载命令；残留扫描只生成永不自动选择的候选。
- “保守选择”只选择规则明确、高置信、统计完整且未占用的候选。正在使用的浏览器或图形缓存会提示先关闭软件；未知大文件、个人资料、残留、重复项、系统托管项和保护内容永不被保守选择。“全部选择”属于用户主动选择，仍会在执行前展示精确目标并确认。
- 普通文件默认移入回收站。永久删除和清空所有本地回收站是两个独立入口，均要求连续两次确认。
- 清理前重新核验规范化路径、保护路径、重解析点、占用状态、大小、修改时间和快照指纹；变化项目跳过。
- 需要系统目录权限时，同一 EXE 以临时管理员执行模式启动，并通过带一次性随机令牌、限制 ACL 的命名管道接收计划；提权端重新执行全部校验。
- 设置、最新扫描快照和指定保留期内的清理记录写入 `%LocalAppData%\DiskCleanupAssistant`，可在设置页一键清除。
- 正式构建每天最多读取一次独立 RSA 签名的更新清单，只提示并打开官方 Release 页面，不下载或替换程序。

## 离线判断机制

- 软件不包含 LLM 或扫描结果上传接口。发布时把版本化 JSON 规则嵌入 EXE，在其他电脑上用本机的 `%LocalAppData%`、`%AppData%`、Windows 目录和用户配置结构展开路径。
- 一条规则可以提供多个路径模板，并展开 `Default`、`Profile *`、版本目录、MSIX 包目录等实际位置；同一软件不同版本不再依赖复制大量固定规则。
- 明确规则项必须同时给出软件归属、用途、路径依据、清理影响、置信度和动作；详情中显示“本地规则 + 规则 ID”，用户可以追溯为什么命中。
- 规则可声明关联进程。Chrome、Edge、Firefox、Discord、VS Code、Cursor、Kiro、Steam 等软件仍在运行时，其候选会标记为占用，不能进入保守选择。
- 深度扫描遇到未知大文件或仅凭目录名发现的缓存时，只显示“本地启发式判断”，不会进入保守选择。重复文件显示“本地完整哈希”，软件残留显示“本地安装信息”。
- 软件保证的是“有证据才建议、证据不足就不自动处理”，而不是保证识别所有第三方软件。自定义安装目录、新版软件目录或罕见应用可能被漏报；这比把未知内容误判成垃圾更安全。
- 无网络时使用 EXE 内置规则照常扫描。规则更新随签名软件版本发布；后续可增加签名离线规则包，但规则不能绕过程序内的保护路径与执行复核。
- 开发依赖仓库、软件残留、未知大文件、系统托管项、重复文件和模型权重不会进入保守选择。`.gguf`、`.safetensors`、`.ckpt`、`.onnx`、`.pt`、`.pth` 等模型文件受到扩展名保护。

## 明确的安全边界

- 不清理注册表、驱动、恢复分区或系统还原点。
- 不关闭用户进程、不安排重启后删除、不提供静默定时清理。
- Windows Update 等系统托管内容只打开 Windows 官方存储清理入口。
- Windows 核心目录、安装修复包、程序安装目录、Git 元数据、数据库、密钥、虚拟磁盘和用户资料库受保护。
- 重复文件组和卸载残留在首版仅供查看，不提供组级删除。
- 扫描本身不修改被扫描磁盘；取消后的界面结果明确标记为不完整。

## 构建

需要 Windows、Visual Studio 2022 Build Tools 的 MSBuild，以及 `.NET Framework 4.8` 桌面编译工具。脚本会在缺少引用程序集时从 NuGet 官方源下载 `Microsoft.NETFramework.ReferenceAssemblies.net48`，它只是构建依赖，不随产品发布。

```powershell
.\build.ps1 -Configuration Debug
.\build.ps1 -Configuration Release
```

Release 脚本会完成重新构建、运行测试，并只复制运行时所需的 `DiskCleanupAssistant.exe` 到 `artifacts`，同时生成 `DiskCleanupAssistant.exe.sha256`。PDB 和测试程序不进入成品目录。

## 代码结构

- `app/UI`：由 `App.xaml`、`MainWindow.xaml` 及其代码组成。
- `app/Scanning`：快速扫描、深度扫盘、重复文件哈希、暂停和取消。
- `app/Rules`：内嵌 JSON 规则、保护规则和保守自动选择策略。
- `app/Cleanup`：即时复核、回收站/永久操作与提权管道。
- `app/Uninstall`：已安装软件清单、官方卸载命令和残留候选。
- `app/WindowsIntegration`：文件身份、占用空间、重解析点和 Shell 集成。
- `app/Updates`：独立签名更新清单验证。
- `app/Services`：本地设置、快照和清理记录。

产品代码保持在同一 WPF 程序集中，规则和更新公钥均嵌入 EXE，不需要额外运行时 DLL。

## 发布门槛

普通 CI 会产出名为 `unsigned-ci-only` 的未签名测试文件，不能作为公开版本。标签触发的公开 Release 必须配置：

- `SIGNING_CERT_BASE64`：可信 OV 或 SignPath 导出的 PFX 内容。
- `SIGNING_CERT_PASSWORD`：PFX 密码。
- `UPDATE_RSA_PRIVATE_KEY_XML_BASE64`：独立更新清单 RSA 私钥 XML 的 Base64。

流水线先把对应公钥嵌入 EXE，再构建和测试，然后执行 Authenticode 时间戳签名、签名验证、SHA-256 生成、更新清单独立签名，最后才创建 GitHub Release。任一凭据缺失或签名验证失败都会阻断发布。

## 当前验收范围

仓库中的自动化测试覆盖内嵌规则、明确缓存整体汇总、快速扫描确定进度、自动选择安全边界、保护路径、应用内置依赖、卸载命令解析、完整重复哈希、变化候选跳过、默认零勾选、永久项不自动勾选、暂停时两秒内取消，以及占位公钥禁用联网。

长路径、无权限目录、占用目录、真实 junction、Windows 回收站、UAC 跨完整性级别管道、测试 MSI 卸载，以及 Windows 10 22H2 干净虚拟机仍属于发布前的系统集成测试；公开 Beta 前必须在隔离 VM 中逐项完成，不能用单元测试结果代替。
